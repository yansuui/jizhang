# 022：旧分配模板名称迁移为标签

## 范围和兼容性

每个未删除的旧模板，其名称会规范化后放入标签目录，并在 `template_tag_mappings` 中保存模板与标签的映射。完全未改名的内置「默认模板」跳过；被用户改名的内置模板会迁移。**旧模板、工资分配快照、账单分类及已有账单标签均不改写**，因此这些新标签最初可能没有关联账单，需要用户自行选择标记；无法从旧的工资分配快照可靠推断每笔账单使用了哪个模板。

同名活跃标签会被复用。若派生 ID 已属于被改名或软删除的其他标签，会创建新的标签 ID，绝不覆盖原标签。已有映射不再重做，因此用户之后删除或重命名标签，重启不会将其复活。旧的 `/api/v1/templates` 仍可读取，创建、修改、删除、设置默认及应用到当前周期均返回 410；旧版 Android/Harmony 的相应操作因此不再可用。

若已运行过本次修复之前的 022，版本记录不会重跑，且为避免覆盖用户的后续编辑，既有映射不会自动改写。请先备份并使用下方核查语句人工检查名称与标签 ID，不要在未确认归属的情况下批量改名或删除。

## 自动迁移（推荐）

升级服务端并启动后，迁移 022 在各用户账本上事务执行；正常升级前迁移器会备份 SQLite 数据库。请提前另行做可恢复的完整备份，并验证包括 WAL 在内的数据。新服务端部署之前，手机上不会出现服务端迁移结果。

## 手工 SQL（仅维修时）

停止服务及所有数据库写入，在每个目标账本上先用 SQLite 备份 API 或 `VACUUM INTO` 建立独立备份。然后运行：

```sh
sqlite3 -bail /path/to/ledger.db < docs/migrations/022-template-to-tag.sql
```

脚本使用事务、只插入新标签及映射、不删改旧表，重复运行安全；它不写 `schema_migrations`，所以服务端之后仍会执行自己的 022，且允许表和索引已存在。手工脚本为防止 SQLite 字符长度与 JavaScript UTF-16 截断规则不一致，遇到超过 32 字符或非 BMP 字符的名称会报错回滚；此类账本请使用自动迁移。手工脚本使用随机标签 ID（ID 是不透明标识，服务端优先按标签名称查找），不保证与自动迁移生成的 ID 字节一致。

## 核查与回滚

```sql
SELECT t.id, t.name, m.tag_id, m.tag_name
FROM budget_templates t LEFT JOIN template_tag_mappings m ON m.template_id = t.id
WHERE t.deleted = 0;
SELECT COUNT(*) AS template_count FROM budget_templates;
SELECT COUNT(*) AS allocation_count FROM budget_allocations;
```

空白模板名不会生成标签；未改名的内置模板也不会生成标签。请与备份对比旧表行数和内容。映射表不记录标签是否在迁移前已存在，因此**不能据映射批量删除标签来回滚**，否则会删除用户原有标签。需要完整撤销时，停止服务后按项目备份/恢复流程恢复事先创建的备份；恢复会回退备份之后的修改，操作前应确认影响。不要删除迁移版本记录以强制重复执行。

## 验证状态

手工脚本及升级路径应在与生产相同 SQLite 版本上先用数据库副本测试。业务数据属于不同用户的独立账本，不要只迁移身份库或另一个用户的账本。
