not merely catalogue descriptions. All additions use the existing v1 conversation,

## Safety and wire contracts

- Tool names are in `ASSISTANT_TOOL_NAMES`; registrations must match exactly. The provider
  receives the catalogue as JSON facts in the existing assistant prompt, not an OpenAI
  native `tools` parameter. Existing bounded step/deadline contracts remain unchanged.
- New adapter schemas reject unknown fields, wrong primitive types and oversized input
  collections. Nested financial references/proposals/templates/refund splits have explicit
  shapes; original domain services remain the authority for business validation.
- Synchronous database-only writers validate and compute a preview inside an explicitly
  rolled-back SQLite transaction. This may increment SQLite's connection-local
  `total_changes()` counter, but persists no rows, operation records or ledger state.
  Tests compare full `db.serialize()` images. No file backup, upload, network request or
  background worker is registered with this preview helper.
- Preview-generated new IDs are temporary and labeled as such. Real domain operation UUIDs
  are server-generated once and persisted in the pending action; a confirm retries that
  exact identity. Stored action ID remains the assistant idempotency identity.
- New write actions hash the private business tables and relevant budget/plan settings.
  Unrelated business edits conservatively expire the draft. Chat/provider settings and
  analysis progress are excluded. Confirmation rechecks inside the same SQLite transaction
  as domain writes, action status, card status and result. Existing domain CAS adds its own
  resource/source checks. The immutable session actor is propagated explicitly.
- The generation-day boundary is also hashed for `recurring.generate`; a card prepared
  yesterday cannot silently generate a wider set of occurrences today. Batch cards report
  actual operation/row counts, and bill/account/category fields include readable names.
- Nine exact SHA-256 concurrency-hash field names are permitted by the JSON normalizer;
  credential/access/session tokens are still refused. These hashes cannot authenticate.
- A stale HTTP confirmation now synchronizes the persisted action and visible history card
  to `expired`; already confirmed actions cannot regress.
- Analysis stores run/audit/checkpoint data only. Date-range results include `totalActions`,
  `offset`, `limit`, `hasMore`; combined action/template pages have at most 100 entries.
  `coverage` reports `eligibleCount`, `completedCount`, `idsOmitted:true`, avoiding silently
  truncating hundreds of evidence IDs. Only selected actions appear in a write preview.
  Large category evidence is returned by `spending.evidence` as paged `{categoryId,amountCents}`
  rows; the card carries `evidenceCategoryCount`/`evidenceTool`, not an oversized dictionary.
  Other large derived nested arrays advertise `truncatedCollections`; primary account,
  salary, recurring, template and trash lists provide true continuation pages.
- Scoped provider instances share spending-run ownership per open private DB. Initialization
  recovery happens before rollback preview; cancellation/deadline can abort nested calls.
  Tenant busy checks pin unfinished work and shutdown aborts/drains it. Draining retires a
  service generation, allowing a new lease on the retained original-owner DB handle.

## Evidence and remaining limits

New `assistant-business-tools.test.ts` uses migrated in-memory databases, immutable member
actors with empty ledger `users`, persisted action cards and the real orchestrator confirm
path. It covers preview rollback, duplicate confirm, expense/income/refund gross accounting,
fund income/config, plans/goals, rules/occurrences, item lifecycle, filtered pagination,
forged/stale/wrong-conversation/foreign-ledger actions, and both organization apply/undo paths.
`multiuser-isolation.test.ts` additionally drives actual authenticated routes for a member's
canonical salary preview/confirm, foreign-owner confirm/cancel refusal and actor persistence.
Existing assistant, provider-stream, organization and tenant lifecycle regressions remain
required. Final command results are recorded in the worker handoff; no live-provider,
production-data, device or deployment verification is implied by these fixtures.

Assistant payload/page bounds are deliberate, and the UI must keep totals/hasMore visible.
Read-only old clients can decode new v1 tool names but may not provide dedicated action
selection/detail/refresh UI; this backend catalogue alone is not proof of client parity.
